# Project Rules

## Общие правила

- Используйте **TypeScript** для всех новых файлов.
- Следуйте соглашениям о наименовании переменных и функций (camelCase).
- Форматируйте код с помощью **Prettier** и следуйте правилам из `.prettierrc`.
- Используйте **ESLint** для проверки стиля кода (конфигурация в `eslint.config.mjs`).

---

## Структура проекта

Проект использует Nuxt 4 с TypeScript и Tailwind CSS. Основные директории:

- **`app/`**: Основная директория приложения.
  - **`components/`**: Компоненты, разбитые по функциональности (например, `auth/`, `ui/`).
  - **`composables/`**: Логика на основе Composition API (например, `useAuth.ts`, `useDealQuery.ts`).
  - **`stores/`**: Логика состояния с использованием Pinia.
  - **`types/`**: TypeScript-типы и интерфейсы.
  - **`utils/`**: Вспомогательные функции.
  - **`constants/`**: Константы и конфигурации (например, `appwrite.ts`, `colors.ts`).

- **`server/`**: Серверная логика (если используется).

---

## Правила для компонентов

- **Имена компонентов**: Используйте **PascalCase** (например, `Button.vue`, `Sidebar.vue`).
- **Структура компонентов**:
  - Разбивайте большие компоненты на более мелкие по функциональности.
  - Используйте **props** для передачи данных между компонентами.
  - Для сложных компонентов используйте **Composition API** (`script setup`).
- **UI-библиотека**: В качестве ui-библиотеки используется `shadcn-nuxt`.

---

## Правила для логики (composables и stores)

- **Composables**:
  - Каждый `composable` должен быть самодостаточным и отвечать за одну конкретную задачу (например, `useAuth.ts` — только аутентификация).
  - Используйте **TypeScript** для типизации возвращаемых значений.
- **Stores**:
  - Используйте **Pinia** для управления состоянием.
  - Разбивайте логику на несколько небольших stores (например, `auth.store.ts`, `deal.store.ts`).
  - Следуйте принципам **immutable state** (изменяйте состояние через методы, а не напрямую).

---

## Правила для типов и констант

- **Types**:
  - Все интерфейсы и типы должны быть описаны в `app/types/`.
  - Используйте `index.ts` для экспорта основных типов.
- **Constants**:
  - Все константы (например, API-адреса, статусы) должны быть описаны в `app/constants/`.

---

## Правила для API и серверной логики

- **Appwrite**: Используйте `app/constants/appwrite.ts` для конфигурации Appwrite.
- **API-запросы**: Логика запросов должна быть вынесена в `composables` (например, `useDealQuery.ts`).
- **Обработка ошибок**: Все API-запросы должны содержать обработку ошибок (например, через `try/catch`).

---

## Правила для стилей (Tailwind CSS)

- Используйте **Tailwind CSS** для стилизации компонентов.
- Следуйте **utility-first** подходу.
- Не дублируйте стили в CSS-файлах, если это возможно.

---

## Правила для тестирования

- Если проект использует тесты (например, Vitest или Jest), добавьте директорию `tests/` и следуйте соглашениям:
  - Каждый компонент должен иметь тесты в `tests/components/`.
  - Логика в `composables` и `stores` должна тестироваться отдельно.

---

## Правила для документации

- Документируйте сложные части кода с помощью **JSDoc** или **Markdown**.
- Обновите файл `docs/project-rules.md` для этих правил.
- Документируйте API и основные функции в `README.md`.
